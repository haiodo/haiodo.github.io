Tenniarb 2.0: макет, который читают и человек, и агент

Дизайн-система и экраны живут в текстовом формате .tenn — править их можно в редакторе и агентом через MCP

Экран входа из библиотеки компонентов. Это не картинка: тот же .tenn, что открывает приложение, нарисованный в браузере. Перетаскивание двигает холст, Ctrl/Cmd + колесо масштабирует, двойной клик вписывает в окно.

Tenniarb — инструмент, в котором макет остаётся текстом: один .tenn-файл с элементами, стилями, компонентами и вычислениями. Из него получаются экраны и компонентная библиотека, а редактируют его и человек в редакторе, и агент через MCP.

Что это

  • Формат .tenn. Один текстовый файл: дерево элементов, свойства, стили, ссылки. Его видно в git, он диффится построчно и открывается любым редактором.
  • Компоненты и параметры. export let объявляет параметры, ${…} подставляет значения на месте use. Повторяющийся блок становится компонентом, а не копипастой.
  • Вычисления в макете. Размеры, отступы и позиции задаются формулами от параметров: меняется значение — пересчитывается всё, что от него зависит.
  • Агент как редактор. MCP-сервер даёт агенту дерево файла, точечную правку текста, проверку ошибок, рендер элемента и комментарии к узлам.

Экран целиком и по частям

Библиотека — это тоже .tenn: элементы, из которых собираются экраны. Ниже — фрагменты, вырезанные прямо из того же документа (каждый встраивается одной строкой).

Контекстные меню: набор команд зависит от того, что под курсором, а не от файла — но описаны они теми же узлами и стилями.

Замечания на узлах: комментарий помнит элемент или точку, к которой привязан, а агент отвечает на него там же.

Как это выглядит в тексте

element "Kit" --from-file "Kit.tenn" // библиотека подключается строкой

element "Card" {
  export let rows = 3
  width 320; auto-layout column; padding 16; gap 8
  item "Title" { title "Заказ"; font-size 16 }
  // высота списка считается от параметра, а не задана числом
  item "List" { height ${rows * 24} }
  use Kit.Button as pay { title "Оплатить"; kind primary }
}

element "Login" {
  item "Window" {
    auto-layout column
    width 344
    gap 12
    item "Header" { title "Вход"; font-size 20; font-weight 700 }
    use Kit.Field as email { title "Email"; hint "name@example.com" }
    use Kit.Field as password { title "Пароль"; kind secure }
    use Kit.Button as submit { title "Войти"; kind primary; width fill }
  }
}

Экземпляр use Kit.Button as pay { kind primary } — тот же компонент с другим вариантом; сам компонент описан один раз, в своём .tenn.

Чем отличается

  1. Макет диффится как код. Не архив и не бинарник: в git видно, что изменилось по узлам — добавлено, удалено, изменено, перемещено, — а откат узла это одна операция undo.
  2. Правки без редактора. Агент читает дерево, меняет свойства точностно и проверяет validate; человек проверяет результат на холсте. Ответить на замечание можно там же — у комментария есть адрес tenniarb://.
  3. Макет считает, а не изображает. Формулы на узлах дают один компонент на все состояния; варианты, которые в статическом макете пришлось бы копировать, получаются параметрами.

Как это начиналось

Первая версия: карта проекта и панель свойств в формате Tenn. В 2.0 тот же формат стал способом описывать дизайн-систему и экраны.

Самый первый макет — мессенджер, задачи и свойства задачи рядом, с жёлтыми заметками прямо на схеме. Он до сих пор открывается одной ссылкой:

tenniarb://open?repo=github.com/haiodo/tenniarb&path=examples/anti-crm.tenn&el=Projects.Tasks.Main%20view

Тот же файл, что и в 2018-м: ссылка называет репозиторий, файл и элемент, поэтому макет открывается у любого, кто склонировал репозиторий, — на любой машине и под любой ОС.
