Tenniarb 2.0: дизайн как текст

Как устроен продукт, зачем у макета текстовый формат и что даёт агентам

В версии 2.0 Tenniarb перестал быть только редактором диаграмм: это инструмент, в котором дизайн-система и экраны живут в текстовом формате .tenn, а рисовать и править их могут и человек, и агент.

Главная идея: один файл, который читают все

Макет обычно существует в трёх несвязанных мирах: картинка в редакторе, компоненты в коде, договорённости в голове дизайнера. Tenniarb сводит их к одному источнику:

element "Button" {
  kind Component
  export let title = "Button"
  export let kind = primary
  styles {
    primary { color #6b3ad3; text-color #ffffff }
    secondary { color #ffffff; text-color #0f121a }
    kind one-of primary secondary
  }
  auto-layout row; height 40; padding 0 16; corner-radius 8
  use-style ${kind}
  item Label { title ${title} }
}

Из этого текста получаются: библиотека компонентов, экраны, экспорт в PNG/PDF/SVG/HTML, и — главное — то, что может читать агент.

Что появилось в 2.0

Компоненты и параметры. Любой item или element может быть компонентом с export let: значения подставляются на месте use, выражения ${…} вычисляются. Макет перестаёт быть копипастой.

Стили и группы. Именованные наборы свойств, каскад в порядке объявления, at поверх всего. Группы one-of/any-of дают инспектору выпадающий выбор варианта — как в дизайн-системе, но без отдельного кода.

Инспектор: варианты из one-of — выпадающий список, значения с fill/hug — переключатель, размеры — поле с числом. Ни одного отдельного описания для панели свойств писать не нужно.

Слоты. Места, куда экземпляр кладёт своё содержимое, включая слоты, объявленные внутри replace; именованный слот компонента-обёртки пробрасывается наружу по имени.

Анимации. animation <имя> <длительность> [easing] [repeat] и блоки кадров. Редактор проигрывает всё по кругу, SVG сохраняет repeat, PNG берёт первый кадр.

Сравнение с git и откат. Режим сравнения показывает, что изменилось, по узлам — добавлено/удалено/изменено/перемещено, — а не по строкам; откат узла к версии из коммита — одна операция undo.

Дерево изменений и панель узла: старое значение рядом с новым, кнопка отката — один undo.

Оптимизатор макета. suggest находит повторяющиеся структуры, одинаковые наборы свойств и мёртвый код; найденное применяется кнопкой с превью и одной undo (компоненты из повторов, именованные стили, удаление лишнего).

Агенты как часть процесса

У Tenniarb есть MCP-сервер: агент читает дерево файла, правит текст точностно, проверяет ошибки, рендерит элемент и оставляет комментарии к узлам. Для дизайн-системы это значит, что перенос макетов, перенос компонентов и ответы на замечания делает агент — а человек проверяет результат на холсте.

Отдельно — комментарии на узлах: замечание привязано к элементу или к точке на экране, у комментария есть адрес, который можно открыть ссылкой tenniarb://.

Технологии

  • .tenn — собственный текстовый формат: элементы, узлы, свойства, ссылки, вычисления.
  • Go — ядро: парсер, раскладка, рендер в PNG/PDF/SVG, компилятор сцены; приложение на gowt (нативное для macOS, Windows и Linux).
  • JavaScriptCore — вычисления в узлах (совместимо с формулами mind-map редактора).
  • TypeScript — веб-версия: просмотр, редактор и встраиваемый рендер для HTML-экспорта.
  • Swift — первая нативная версия, остаётся в репозитории как история.

Где это применяется

На Tenniarb переносится дизайн-библиотека Intabia Platform: UI-kit, рабочий стол, трекер, чат, настройки, вход и профиль — как .tenn-библиотеки и экраны, из которых затем генерируются Storybook и код.
